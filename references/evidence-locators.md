# 证据回链与定位格式

每条命中都必须能被第三方从 `result.json` 独立复现到同一段原文。回链由三层组成：文件身份、位置、片段。

## 1. 文件身份

```json
{
  "file": "01_project/2021-buffer-notes.md",
  "sha256": "<文件字节的 sha256>",
  "bytes": 1832,
  "extractor": "text/utf-8",
  "encoding": "utf-8"
}
```

- `file` 是相对输入根的 POSIX 路径，不是机器绝对路径。
- 若文件在字节上限处被截断，`hash_scope` 为 `prefix`，此时哈希只覆盖已读取前缀，不能当作整个文件的指纹。
- 重复内容按 `sha256` 识别；后出现的副本写入 `duplicates`，不重复计入证据。

## 2. 位置 locator

文本文件：

```json
{"kind": "line", "line_start": 12, "line_end": 18, "char_start": 210, "char_end": 388}
```

- `line_start` / `line_end` 为原始文件 1 起算行号，是人工复核的首选定位。
- `char_start` / `char_end` 为抽取文本中的字符偏移，用于程序化定位；HTML/XML 抽取后偏移对应的是去标签文本，不是原始字节。

PDF：

```json
{"kind": "page", "page": 4, "char_start": 5120, "char_end": 5290}
```

- 页码由 PDF 页面对象顺序启发式推出，可能与印刷页码错位。
- PDF 命中 `confidence` 固定为 `low`，不得在交付说明中宣称精确页码。
- 无文本层扫描件不会产生命中，只会出现在 `skipped` 中，原因 `no_text_layer`。

## 3. 片段 quote

- `quote` 是命中段落中的连续原文片段，默认约 320 字符，围绕最早出现的最长匹配词截取。
- `quote_sha256` 是 `quote` 的 UTF-8 字节 sha256，用于快速比对是否被改动。
- 复核时逐字比较：打开 `file`，跳到 `line_start` 或 `page`，确认 `quote` 确实出现在该位置；标点、空白与换行以原文为准。
- 若 `quote` 为空、只包含文件名、或无法在定位点找到，该命中不可用，必须在 `run-review.md` 中标记失败，不能保留为有效证据。

## 4. 置信度

| 值 | 含义 |
|-|-|
| `high` | 文本正常解码，命中多个不同查询词 |
| `medium` | 文本正常解码但仅命中一个词，或片段上下文较短 |
| `low` | PDF 启发式抽取、Latin-1/替换字符解码、或截断文件 |

低置信命中可以用，但必须在 `uncertainty` 与复核记录中说明，不能与高置信命中混为一谈。

## 5. 回链检查清单

- [ ] `file` 存在且相对路径可在输入根下解析。
- [ ] `sha256` 与当前文件一致（完整哈希时）。
- [ ] `line_start` 指向的行确实包含 `quote` 的首句。
- [ ] `quote` 与原文逐字一致（允许因截取产生的首尾空白差异）。
- [ ] PDF 页码只作为近似定位，不作为印刷页码结论。
- [ ] 证据不足时返回空命中并写 `misses`，不以文件名相似冒充正文命中。
