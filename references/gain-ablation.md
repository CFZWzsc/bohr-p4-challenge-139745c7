# 对照与增益证据（filename-only 基线 vs 本 Skill）

> 本文件记录提交者对同一 demo 案例的一次实测对照。基线实现不随包提交，口径见下：
> 只把查询词与文件名比对，命中即返回整篇文件，不读正文、不给定位与引文。
> 数值不代表平台正式案例结果，也不冒充白板。

- 案例目录：`examples/demo-case`，输入文件 6 个，查询 2 条
- 入口退出码：0；`status`：partial
- 基线（只按文件名匹配查询词）：命中文件 0 次，定位粒度=整篇文件，无段落/页码与逐字引文
- 本 Skill：段落级命中 8 条，其中带 locator+逐字 quote 8 条（100%），可逐条打开原文核对

| 查询 | 基线文件名命中数 | 基线示例命中 |
|---|---:|---|
| buffer recipe Tris NaCl pH | 0 | （0，文件名不含查询词） |
| flow cytometer calibration | 0 | （0，文件名不含查询词） |

## 差异结论

1. 命名不具备区分度时，基线给出 0 命中（2/2 条查询），本 Skill 仍可从正文召回候选段落并在 `misses` 中如实说明未命中原因。
2. 基线只能给到整篇文件，本 Skill 的 8 条命中均带行号或页码、章节与逐字片段，复核者按 `locator` 跳转即可比对该段原文。
3. 所有数字均由同一次确定性运行产生，重复执行结果一致；基线不复用本 Skill 的索引或过滤逻辑。
